## 一、项目是什么
基于 **Tauri 2 + React 19 + Node sidecar** 的 AI 编程助手桌面端。下层的真实 AI 引擎是 **PI（@earendil-works/pi-coding-agent）**——本程序不实现任何 AI 逻辑，只是把「终端 PI」包一层桌面 UI（会话/项目/技能/工作区管理），通过 JSONL over stdio 与 sidecar 通信。

- 目录：`L:\projects\PI-GUI`
- 当前版本：**0.3.5**（下一版待打，见「正在推进」）
- Git：`main` 分支，已推送到 GitHub `dongdong-agent/PI-Desktop`

## 二、技术栈
- 前端：React 19 + TypeScript + Vite + zustand（状态）+ react-markdown（渲染）
- 桌面壳：Tauri 2（`decorations:false` 自定义标题栏、`transparent` 圆角窗口）
- 驱动层：Node sidecar（`drivers/sidecar/sidecar.mjs`），JSONL over stdin/stdout
- 打包：NSIS（setup.exe）+ MSI，per-user 安装到 `%LOCALAPPDATA%\PI Agent`

## 三、目录结构（高频）
- `src/ui/`：Sidebar（侧栏）、PiChatView（主对话区）、SettingsPanel（设置）、TitleBar、MarkdownBody、ToolTimeline、icons.tsx（线性图标集）
- `src/pi/`：bridge.ts（前端 IPC→sidecar）、piUiStore.ts（zustand 全局态）、eventModel.ts（事件状态机）
- `src/app/`：App.tsx（根/快捷键）、theme.ts（7 套主题 token）、bootstrap
- `drivers/sidecar/sidecar.mjs`：PI 驱动翻译层（**唯一业务后端**）
- `src-tauri/src/`：pi_bridge.rs（spawn sidecar + 命令桥）、window_cmd.rs、pet.rs
- `src-tauri/resources/`：**打包用副本**（node-win-x64、pi-package、drivers/sidecar/sidecar.mjs）——注意 drivers 源与这里的副本要手动同步

## 五、关键修复与踩坑（重要）
1. **`\\?\` 路径前缀 bug（已修，0.3.5）**：Windows `resource_dir()` 返回带 `\\?\` 的 verbatim 路径，sidecar 用 `pathToFileURL+import` 加载 `PI_GUI_PI_DIST` 时会**崩溃秒退**，导致应用连不上 PI。Rust 侧加了 `clean_path()` 去掉前缀。
2. **sidecar 黑窗（已修）**：GUI 父进程 spawn 控制台型 node 子进程会弹黑窗，给子进程加 `CREATE_NO_WINDOW`。
3. **自包含（已修，0.3.5）**：sidecar 必须随安装包走 `resources/drivers/sidecar/sidecar.mjs`，不依赖开发目录。tauri `resources` 里不要用 `../`（会映射到 `_up_`）；`pi_bridge.rs` 的 `sidecar_path` 现优先 `resources/drivers/...`。
4. **事件解析失败误报（已修，前端）**：sidecar stdout 是纯 JSONL；空行/噪声行被前端当错误。`bridge.ts` 空行直接忽略、非 JSON 仅 console 记录。
5. **诊断手段**：`pi_bridge.rs` 会把 spawn 详细日志写到**安装目录 `pi-bridge.log`**（解析到的 resource_dir/node/sidecar/pi_dist、spawn 结果、子进程早退），排障优先看它。
6. **devtools 权限名坑（正在验证）**：Tauri 没有 `core:webview:allow-open-devtools`（存在的是 `allow-internal-toggle-devtools`）；且 `Manager::get_webview/webviews` 被 `#[cfg(feature="unstable")]` 门控，需给 tauri 加 `unstable` feature。**F12 功能正在修这条链路（见下）**。

## 十一、规划（待开工）：多会话并行（B 方案）与「进行中」运行列表

**现状与根因（已确认）**：当前是**应用级单 sidecar + 单一全局 session**；
- `drivers/sidecar/sidecar.mjs` 维护 `let session = null`（唯一 AgentSession）；主循环 `void handleCommand(cmd)` **不串行等待**，多个请求会同时打进同一会话。
- `src-tauri/src/lib.rs` 里 bridge 是**应用级单例**（setup 里 `app.manage(bridge)` 只建一次），所有窗口（含新窗口）共享同一驱动与上下文 → **无法多对话并行**。

**目标**：支持「单应用内多对话并行」，并在**项目列表上方**新增独立折叠区 **「进行中（N）」**（命名已定），统一列出正在跑的对话，类似 Hermes agent 的 live sessions。

### 分期
- **P1｜sidecar 多会话池**：`let session` → 按会话 id 的会话池 `Map<id, AgentSession>`，每对话独立上下文/模型；事件携带 `sessionId`；新增 `list_active_sessions` 指令上报「活跃会话清单」（会话名 / 所属项目 / 状态 / 模型）。
- **P2｜前端「进行中」区 + 事件路由**：侧栏项目上方加「进行中（N）」折叠段（样式与其它分区一致）；每项 = 会话名 · 项目名 · 状态点 · 模型 · 可**停止 / 点击跳转**；主对话区按 `sessionId` 绑定，切会话**不打断流式**（A 切到 B，A 仍在后台跑，切回 A 状态还在）。
- **P3｜打磨**：状态机（flowing / thinking / idle）、异常恢复、空闲自动移出或保留最近 N 条。

### 关键改动点（实施时参考）
- `drivers/sidecar/sidecar.mjs`：全局 session → 会话映射；`init/prompt/switch/fork/compact/abort` 按 session 路由；新增活跃会话指令。
- `src-tauri/src/pi_bridge.rs`：事件转发带上 `sessionId`（P1 先单进程多 session）。
- `src/ui/Sidebar.tsx`：新增「进行中」分区（项目列表上方）。
- `src/pi/piUiStore.ts`：新增 `activeSessions` 状态 与更新/跳转 action。
- `src/pi/eventModel.ts`：消息/工具按 sessionId 隔离。
