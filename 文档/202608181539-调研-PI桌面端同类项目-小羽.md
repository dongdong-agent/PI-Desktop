> 版本：v1.0 · 调研人：小羽 · 2026-08-18 · 方法：GitHub 搜索 + README/架构文档研读
> 结论先行：**PI 桌面端是个正在快速起量的赛道**（GitHub 上已有 5 个专做 PI 的桌面端 + 2 个大型多-agent 平台），

## 二、界面处理方式对比（核心问题：他们怎么布局）

### 1. 整体布局
- **单栏对话流**（最简）：消息时间线 + 底部输入（我们的现状；abcwyc 初期形态）
- **三栏布局**（成熟主流）：左=会话/项目树，中=对话流+composer，右=信息面板（工具调用时间线/产物预览/运行历史）——**zosma-cowork、opencode 系、Claude Code 桌面端均为此范式**
- **双面板**（中档）：左=会话列表，右=对话流，终端做底部 docked 面板（gustavonline/pi-desktop）

### 2. 对话流（消息区）
- 每条消息：role 标识 + 内容块（文本/思考折叠/工具调用卡片/工具结果）
- **工具调用展示**分两种：内联卡片（如我们现状） vs **独立时间线面板**（右栏按时间顺序列所有工具执行，左栏保持纯对话）——后者更清晰，zosma/orca 采用
- **思考块默认折叠**为可展开（一致做法）
- **composer**（输入区）：Codex 风格，支持斜杠命令、`/skill:name` 预渲染为技能 pill（gustavonline 的亮点交互）

### 3. 会话管理
- 共同点：会话侧栏 = 项目分组 + 会话列表（首条消息为标题、时间、消息数）
- 进阶：**重命名/置顶/删除/文件夹分组**（zosma）；**在任意历史消息处分叉（fork）或 clone**（abcwyc）；**会话树（/tree）跳转**（pi 原生能力）
- 数据均复用 `~/.pi/agent/sessions/`（与终端共享）——我们已实现

### 4. 项目/工作区
- **按项目组织会话**（一致）；进阶：**Git worktree 管理**（abcwyc：侧栏切 worktree + 浏览项目文件）；**文件预览器**（代码/diff/Markdown/图片/PDF/DOCX——abcwyc 独有亮点）

### 5. 模型与上下文
- 模型选择器（一致）；进阶：**每会话独立模型覆盖**（zosma）
- **上下文状态可视化**（重要且普遍）：token/cost/context 占用百分比常驻显示（abcwyc/openpi 均有），compaction 状态可见——**这正是我们 P1 要做的，且是同类标配**

### 6. 能力扩展（技能/扩展/命令）
- 统一做法：侧栏或独立面板浏览 skills/扩展，**点击即发送 `/skill:name`**（我们已实现基础版）
- 进阶：扩展 App Store UI（安装/启用/禁用/配置面板，zosma）；slash 命令面板 + 命令调色板（Ctrl+K）

### 7. 输入区增强
- `@` 文件引用 + 模糊搜索（zosma 部分完成、abcwyc 有文件浏览）
- 图片/文件拖拽附加（多个项目在 roadmap）
- `!cmd` 发 shell 命令给模型（pi 原生语法）

### 8. 其他亮点
- **终端面板**：docked 底部面板（gustavonline/pi-desktop 已做，很实用）
- **完成提示音 + 系统通知**（abcwyc）
- **远程/手机伴侣**：嵌入式 server + QR 配对（orca/zosma/codeg 均涉足——远程监督是方向）
- **主题**：深/浅色是标配（我们已有）；zosma 有品牌色变体
- **自动更新**：abcwyc 有完整升级链路（下载签名新包自动重启）

## 三、共性模式提炼（大家都在这么做 = 已验证的正确方向）

1. **三层职责边界**（openpi 定义最清晰）：Renderer 只渲染 UI 意图；主进程管特权操作；**PI SDK 管全部 agent 语义**——不做任何 agent 逻辑复刻（与我们一致）
2. **会话/模型/技能/扩展 全部复用 ~/.pi/agent 真实数据**（一致，无需自建）
3. **工具调用独立时间线 + 左对话右信息的三栏布局**是成熟形态
4. **token/cost/context 占用可见 + compaction 可控**是标配（不是加分项）
5. **composer 化输入区**：斜杠命令、技能 pill、@ 文件引用
6. **项目 = 组织单位**：按项目分组会话、切项目切上下文

---

## 四、差异化机会（别人没做好的，我们可做）

1. **多 Agent 协同工作台**：orca 只做并行展示、codeg 做委托但重；把「PI 主 Agent + 任务板」做轻做顺仍有空间
2. **技能库可视化做得更聪明**：不只是列表点击，而是「技能 → 可配置参数 → 一键执行」的表单化（呼应东哥的「提示词库/素材库」愿景）
3. **桌面宠物/皮肤系统**：同类均无——这正是东哥的差异化愿景（皮肤 token 已就绪，宠物可做独立窗口模块）
4. **中文母语化体验**：同类项目英文为主，中文体验（含中文技能生态）是天然壁垒
5. **手机伴侣**（orca 验证了需求）：未来可通过嵌入式 HTTP+WS 扩展

## 五、对我们的启示与下一步建议

### 已验证正确（不用改）
- ✅ 架构：React → Rust → Node sidecar → PI SDK（与 zosma 同构，且我们是 Tauri 更轻）
- ✅ 会话/项目/模型/技能复用真实 PI 数据
- ✅ 输入框下方工具栏（用户要求的位置）

### 建议的下一步（按优先级）
1. **P1（本周）**：上下文状态栏（token/cost/context%）+ 手动 compact + 思考级别调节 —— **同类标配，补上才及格**
2. **P1.5**：工具调用右信息面板雏形（把 tool timeline 从对话流中抽到右栏，主区更干净）
3. **P2**：composer 增强（`/skill:name` 技能 pill、斜杠命令提示、`@` 文件引用）
4. **P2**：会话重命名/置顶/删除 + 分叉（fork/clone）
5. **P3（差异化）**：皮肤系统深化（多套主题 token）、技能参数化表单、桌面宠物占位
6. **远期**：终端 docked 面板、完成提示音、远程监督

> 建议：先做 P1（补齐标配），再做 P2 的 composer 增强（交互质感提升明显），
> 差异化项（皮肤/宠物/技能表单）可穿插——它们是我们区别于同类项目的关键。
